- [ ] **[DEBT] `importDiscoveredProject()`'s CSV header parsing has no legacy-shape migration at all.** Found while adding the core Notes column (backlog #22): `applyImportedCSVData()` (used by manual Import and Dropbox "Restore") has always handled a CSV exported before Labels (and now Notes) existed by detecting the missing header and splicing in a blank column at the right position, so older exports still land every custom column correctly. `importDiscoveredProject()` -- the "Check Dropbox for other projects not in this browser" bulk-import path -- parses headers the same way (`headers.slice(N)`) but has never had that same legacy-shape check, so importing a very old cross-device backup (predating Labels, or now predating Notes) through *that* specific path would misalign its custom-column data by one or two slots instead of shifting it correctly.
